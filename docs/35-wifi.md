# 35 - Wi-Fi: OEM board data and the MAC address (2026-11-27)

## OEM board data (bdwlan.elf)
- ath11k's `board-2.bin` entries for the QCA6390 are whole `bdwlan.elf` files (57,908 bytes). The stock `persist/bdwlan.elf` of this phone (extract it from the `persist` backup, `tools/extract-*` style: `7z x persist.img bdwlan.elf`) differs from the generic entries in 6,600-7,600 bytes (this phone's calibration/power limits).
- `tools/make-ath11k-board.py --bdwlan bdwlan.elf --board-2 <linux-firmware board-2.bin> --variant realme_GT_Neo_2 -o board-2.bin` adds the entry `bus=pci,qmi-chip-id=0,qmi-board-id=255,variant=realme_GT_Neo_2` (the format matches the existing entries; the rebuild of an unmodified file differs only in padding bytes after the magic). Output sha256 `f5f3244b1be6fb46aeffd73133c013948d0abcc1ee3b541f342714a9ca6f212f` (generic linux-firmware 20260519 + our entry). The file is device specific: kept in the gitignored `third_party/firmware/ath11k/QCA6390/hw2.0/board-2.bin`; the initramfs and rootfs builders prefer it over `/usr/lib/firmware`.
- DT: `&wlan0 { qcom,calibration-variant = "realme_GT_Neo_2"; };` (kernel fork `eb7a65263`). The variant is in the live device tree (`/proc/device-tree/.../wifi@0/qcom,calibration-variant`). ath11k is built without `CONFIG_ATH11K_DEBUG` here, so it never logs the board name it picked.
- **Evidence that the OEM entry is used**: with the generic entry the firmware reports the placeholder MAC `00:03:7f:12:ae:ae`; with the OEM entry it reports `00:00:00:00:00:00` and NetworkManager fails activation ("failed to reset MAC address to 00:00:00:00:00:00"). The OEM board data therefore does not carry a MAC: the host is expected to provide it (the stock Android "use-nv-mac").
- Note: a DT change only reaches the phone through the kernel image (the DTB is embedded via `CONFIG_BITRA_DTB_SHIM`): rebuild `Image.gz` as well as the dtb (the first `a-31` booted without the variant for exactly that reason).

## MAC address
- Nothing in `persist` holds a Wi-Fi/BT address (`persist/wlan` has only WCNSS_qcom_cfg.ini and two cnss_diag configs; no `wlan_mac.bin`). Where stock Android gets it from was not found (modem NV / oplusreserve not searched in depth). ath11k in 7.2 has no `local-mac-address` DT support.
- Solution: OpenRC service `bitra-wifi-mac` (rootfs-overlay) sets a locally administered address `02:xx:xx:xx:xx:xx` on `wlan0` before NetworkManager starts, derived from the SoC serial (`/sys/devices/soc0/serial_number`, hash of `bitra-wlan:<serial>`), so every phone gets its own stable address. This phone: `02:4e:83:93:af:e1`. NetworkManager config `bitra-wifi-mac.conf`: `wifi.cloned-mac-address=preserve`, `wifi.scan-rand-mac-address=no`. Tested live: associates, DHCP, internet (29-49 ms to 1.1.1.1).
- Bluetooth address: still the fixed `local-bd-address` in the DT (02:b1:7a:05:5a:ad); the same SoC-serial derivation can be done in userspace once `btmgmt` is available (not installed).
